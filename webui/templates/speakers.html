A diarizer labels voices SPEAKER_00, SPEAKER_01 - cluster ids, not people. Something has to decide that SPEAKER_01 is Nancy. Until ADR-010 that was a paid reasoning model, on every single run, and when it guessed wrong the only fix was editing the transcript by hand - which the next full run overwrote (see the warning in whycast/pipeline/speakers.py:write_merged_transcript). ADR-010 turns the decision into a file the pipeline reads. This page is that file, with a form around it. MONEY. Saving is free and takes no confirmation: it writes one small JSON file. Applying the names is the "speakers" job, which re-runs the paid OpenAI steps, so it goes through the same POST /api/jobs, the same $ badge and the same confirmation as every other paid action here. There is no "save and run" button, on purpose - the two have different prices and are therefore two different decisions. Nothing here uses |safe. The names come from a file a person (or a model) wrote, the context lines are transcript text, and both are rendered as text. #} {% extends "base.html" %} {% block title %}Speakers - {{ episode.base_name }} - WHYcast{% endblock %} {% block content %} {% import "_macros.html" as m %}
