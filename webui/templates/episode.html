{# Artifact tabs. SECURITY - read before changing the swap mechanism. Artifact files are not trusted input. They are LLM output generated from podcast audio and feed text over years of runs, and anything that can write to podcasts/ can edit them. An artifact containing is a realistic case, not a hypothetical. So artifact content is never brought into THIS document. Each tab is a plain link whose target is the sandboxed iframe below, which means the browser *navigates* to the artifact instead of splicing it into the live DOM. That distinction is the whole fix: * A previous version used hx-get + hx-swap="innerHTML". A response header cannot govern a string handed to innerHTML - there is no browsing context to apply it to - so the API's `Content-Security-Policy: sandbox` was inert and inline handlers executed in the app's own origin. htmx parses every response body into a fragment regardless of Content-Type, so a text/plain transcript was just as dangerous as an .html blog. * As an iframe navigation, that same `sandbox` header now genuinely applies, and the sandbox attribute here applies a second time on the embedding side. With no allow-* tokens there is no scripting and the frame gets a unique opaque origin, so hostile content cannot reach this page, its DOM, or the API. This also works with JavaScript disabled: target= is plain HTML. app.js only marks the active tab. #}
